# کارا پرداز اوند — پکیج پرامپت فاز به فاز

نسخه ۱ · Next.js + Tailwind · RTL-first · تم روشن پیش‌فرض

## طرز استفاده

- هر فاز را جداگانه به ایجنت بده و فقط بعد از تایید معیارهای پذیرش به فاز بعد برو.
- فاز ۰ را یک بار در فایل AGENTS.md یا CLAUDE.md پروژه بگذار؛ بقیه فازها را به‌ترتیب در چت بفرست.
- پرامپت‌ها انگلیسی هستند چون ایجنت‌ها دقیق‌تر اجرا می‌کنند؛ متن‌های سایت فارسی است.
- فایل HTML پیش‌نمایش هیرو را همراه فاز ۴ ضمیمه کن (مرجع بصری و رفتاری).
- اگر خروجی ایراد داشت، از قالب «پرامپت اصلاح» در انتهای سند استفاده کن.

## فاز ۰ — نقش و قوانین کلی (یک بار)

```
ROLE
You are a senior frontend engineer and product designer building the official website of Kara Pardaz Avand (کارا پرداز اوند), a software company and sister brand of Code1Sprint.

BUSINESS
Services: custom software design, websites of every type, CRM, ERP, RAG and enterprise AI, data science.
Audience: Iranian businesses and organizations, operations managers, CTOs.
Language: Persian first (RTL), English second.
Tone: calm, precise, trustworthy. Outcome-oriented copy, no hype, no invented claims.

VISUAL DIRECTION
Modern, minimal, software-native. Visual vocabulary: system maps (nodes and edges), console logs, status badges, dashboards, code snippets. Light theme is the default; dark theme is supported.
FORBIDDEN: blueprint or drafting grids, dimension lines, architectural or construction metaphors, stock photos of people, walls of identical SaaS cards, purple gradient washes, emoji as icons.
Spend visual boldness in ONE place per page; everything around it stays quiet.

ENGINEERING RULES
- Next.js (App Router), TypeScript strict, Tailwind CSS, motion (Framer Motion), next-intl (fa default, en secondary).
- RTL-first: logical properties only (ms-, me-, ps-, pe-, text-start). Never left/right.
- Colors, radii and spacing come from design tokens (CSS variables). No hard-coded hex in components.
- Server Components by default; client components only for interaction.
- Content lives in /src/content (typed TS or MDX), never inline in JSX.
- Accessibility: semantic HTML, visible focus, full keyboard support, prefers-reduced-motion respected, AA contrast.
- Never invent clients, testimonials, statistics or logos. Where real data is needed, render nothing or use a TODO_REAL_DATA marker in the content file.

WORKFLOW
Work phase by phase. For each phase: (1) short plan, (2) implement, (3) run lint, typecheck and build, (4) report: files changed, how to run, acceptance checklist with pass/fail, open questions. Do not start the next phase.
```

## فاز ۱ — اسکلت پروژه

```
PHASE 1 - PROJECT SCAFFOLD
1. Create a Next.js app: TypeScript, App Router, Tailwind, ESLint, src directory, import alias @/*.
2. Install: motion, next-intl, zod, react-hook-form, clsx, tailwind-merge. Dev: prettier, prettier-plugin-tailwindcss.
3. i18n routing with next-intl: fa (default) and en. Set html lang and dir per locale (rtl for fa, ltr for en).
4. Folder structure:
   src/app/[locale]/...  src/components/{ui,layout,sections}  src/content  src/lib  src/styles/tokens.css  messages/{fa,en}.json
5. tsconfig strict. Scripts: lint, typecheck, format.
6. Add .env.example with NEXT_PUBLIC_SITE_URL, NEXT_PUBLIC_PARENT_BRAND_URL, CONTACT_WEBHOOK_URL.
7. Add AGENTS.md containing the Phase 0 rules.

ACCEPTANCE
- Dev server runs; /fa renders RTL and /en renders LTR.
- lint, typecheck and build pass with zero warnings.
```

## فاز ۲ — سیستم طراحی و کامپوننت‌های پایه

```
PHASE 2 - DESIGN SYSTEM
1. Implement src/styles/tokens.css with the light and dark tokens from the design token section. Light is the default; dark values apply only when html has data-theme=dark. Map tokens into the Tailwind theme.
2. Fonts via next/font: Vazirmatn (400, 500, 700, 800) and JetBrains Mono (400, used only for console/log/code).
3. Theme toggle: persists in localStorage, applied by a tiny inline script before paint (no flash). Default is light regardless of OS setting until the user toggles.
4. Build typed, accessible components in src/components/ui: Button (primary, secondary, ghost; 48px height), Container, Section, Card (1px border, no shadow), Badge (with status dot), Tabs (ARIA tablist; arrow keys must respect RTL), Accordion, Input, Textarea, Field (label, hint, error).
5. Create a /[locale]/design route that renders every component in both themes.

RULES
- No component may use a hard-coded color.
- Focus ring: 2px accent outline with 3px offset on every interactive element.

ACCEPTANCE
- /fa/design looks correct in light and dark, desktop and mobile.
- Keyboard-only navigation works on Tabs and Accordion.
```

```
PHASE 4 - HERO WITH INTERACTIVE SYSTEM MAP
Reference: the attached kara-hero-preview.html. Match its behavior and look, but restructure into clean components (HeroSection, SystemMap, ConsoleLog) with typed data in src/content/systems.ts.

COPY (fa)

Provide the English version in messages/en.json.

LAYOUT
Two columns from 900px up (text first in RTL), single column below.

SYSTEM MAP PANEL
- Tabs: CRM, ERP, RAG و AI, داده, وب‌سایت (data-driven).
- SVG viewBox 560x250. Five nodes 130x44, radius 10: inputs at (480,60) and (480,190), core at (280,125), outputs at (80,60) and (80,190). Four cubic edges: input to core (2), core to output (2).
- Core node: accent border, accent-soft fill, bold accent label. Other nodes: bg fill, line border.

ACCEPTANCE
```
