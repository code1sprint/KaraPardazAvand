## مسئله

پروژه‌هایی که همه قابلیت‌ها را در یک تحویل بزرگ جمع می‌کنند، معمولاً دیر بازخورد می‌گیرند و اصلاح مسیر هزینهٔ بیشتری دارد.

## رویکرد

دامنه را به برش‌های قابل‌استفاده تقسیم می‌کنیم: هر مرحله یک نتیجهٔ مشخص برای کاربر یا عملیات دارد، نه فقط یک بستهٔ فنی.

```ts
type Milestone = {
  outcome: string;
  acceptance: string[];
  owner: "client" | "team";
};

const plan: Milestone[] = [
  {
    outcome: "ورود و نقش‌ها",
    acceptance: ["ورود امن", "سه نقش پایه"],
    owner: "team",
  },
];
```

## نتیجهٔ مورد انتظار

تصمیم‌گیری زودتر، شفافیت وضعیت، و امکان توقف یا تغییر مسیر بدون دور ریختن کل سرمایه‌گذاری.

### نکته

جزئیات زمان‌بندی و معیار پذیرش برای هر پروژه جداگانه تعریف می‌شود.
